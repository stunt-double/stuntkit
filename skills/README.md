# Skills

[Agent Skills](https://agentskills.io) for the StuntKit packages. Each one teaches a coding agent when to reach for a package, how to wire it up, and the mistakes to avoid, so it gets the integration right the first time. Longer material (full agent loops, framework recipes, the icon catalogue) sits in each skill's `references/` folder and is read only when needed.

## Install

As a plugin from this repository's marketplace:

```sh
/plugin marketplace add stunt-double/stuntkit
/plugin install stuntkit@stuntkit
```

Any agent that reads Agent Skills (a `SKILL.md` per folder): copy the folders you want into your project's skills directory, or install them with a skills installer that reads GitHub repositories.

## Writing a skill

A skill belongs here when it helps someone use a published package. Skills for working on this repository are [project skills](../.claude/skills) instead.

- One folder per package, named `stunt-double-<package>`, holding a `SKILL.md` with `name` (matching the folder) and `description` frontmatter. Workflows that span packages are named `stuntkit-<task>`.
- The description says when to use the skill, in the words a developer would use for the task, not just the package name.
- Lead with the decision (which entry point or surface), then the code, then the mistakes. Keep `SKILL.md` under about 150 lines and move longer material into `references/`, linked from `SKILL.md` with what each file holds.
- `stunt-double-icons/references/catalogue.md` is generated by `pnpm --filter @stunt-double/icons generate`; do not edit it by hand.
- Update the skill in the same pull request as the package change it describes, and bump `version` in [the plugin manifest](./.claude-plugin/plugin.json). This folder is the plugin root, so keep anything that is not a skill or an agent out of it.
